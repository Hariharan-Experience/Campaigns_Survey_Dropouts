  Implementation Plan

  Overview

  A Campaign Analytics Dashboard in React/Vite that demonstrates survey dropout
  patterns and intelligence features using mock data. Two main sections with
  analysis, visualization, and an Anthropic integration backend to generate
  insights.

  Key Features

  1. Dropout Insights Section
     - Visual funnel showing where respondents drop out across survey questions
     - Friction metrics (% completion, avg time per question)
     - Comparison with previous period (period-over-period metrics)
     - List of questions ranked by dropout rate
  2. Response Intelligence Section
     - Sample respondent feedback quotes
     - Thematic patterns (grouped by question)
     - AI-generated improvement suggestions powered by Claude API
     - Actionable recommendations for high-friction questions

  Proposed File Structure

  hackathon-aug26/
  ├── package.json (root — Vite config + dependencies)
  ├── vite.config.js
  ├── src/
  │   ├── main.jsx (Vite entry point)
  │   ├── App.jsx (router setup)
  │   ├── index.css (global styles)
  │   ├── pages/
  │   │   └── CampaignAnalytics.jsx (main dashboard page)
  │   ├── components/
  │   │   ├── DropoutInsights.jsx (funnel viz, metrics table)
  │   │   ├── ResponseIntelligence.jsx (feedback section)
  │   │   ├── MetricCard.jsx (reusable card for KPIs)
  │   │   ├── ComparisonBadge.jsx (period-over-period indicator)
  │   │   └── LoadingSpinner.jsx
  │   ├── data/
  │   │   └── mockData.js (campaigns, questions, dropouts, feedback)
  │   └── utils/
  │       └── api.js (calls to localhost:5000 for Claude insights)
  ├── server/ (Express.js backend)
  │   ├── server.js (main entry point)
  │   ├── routes/
  │   │   └── insights.js (POST /api/insights — Claude API integration)
  │   ├── package.json
  │   └── .env (ANTHROPIC_API_KEY)
  └── README.md (how to run)

  Tech Stack

  - Frontend: React 18, Vite, React Router v6, Plain CSS
  - Backend: Node.js + Express (localhost:5000)
  - Anthropic: Claude API for generating improvement suggestions
  - Data: Mock survey campaigns, questions, respondent data
  - No auth, no DB, no Redux

  MVP Scope (3 hours)

  1. Mock data: 2–3 campaign examples with 8–10 questions each, simulated
     dropout rates, sample feedback
  2. Frontend dashboard: Responsive layout with two sections, basic CSS styling
  3. Visualization: Simple dropout funnel (HTML/CSS bars), metric cards
  4. Backend: Single /api/insights endpoint that calls Claude with context and
     returns improvement ideas
  5. Integration: Frontend fetches insights, displays them in Response
     Intelligence section

  What It Shows

  - Researchers can see where surveys fail (dropout funnel)
  - They understand which questions cause friction (friction ranking)
  - They know what respondents are saying (sample quotes grouped by question)
  - They see trends (this campaign vs last quarter)
  - They get actionable fixes (AI-generated improvements powered by Anthropic)

⏺ Dropout Insights is built and verified in the browser.

  What's calculated

  src/utils/dropout.js derives everything from raw reached/dropped counts — no
  rate, delta, or status is stored in the data:

  dropoutRate     = dropped / reached
  completionRate  = completed / invited        (cumulative)
  change          = dropoutRate − previousDropoutRate
  status          = <10% Healthy · 10–20% Watch · ≥20% High friction

  worstRow() and mostWorsenedRow() find their targets by reduce — the callouts
  read "Q5 · 21.1%" because it computed to be the max, not because Q5 is named
  anywhere in the component.

  Funnel + table

  The funnel plots each stage as a share of all 10,000 invited: blue =
  continued, orange = dropped there, 2px gap between them. Q5's orange block is
  visibly the story. Table carries all eleven columns you listed, with per-row
  Analyze wired to real selection state — it highlights the row and funnel bar
  and feeds the question into the Response Intelligence card below.

  Two decisions you should know about

  I changed the mortgage data. Nothing in the original funnel reached 20%, so
  the High friction tier would never have rendered. I deepened Q5 from 1,240 →
  1,780 drops (14.7% → 21.1%) and thinned the tail to compensate. All invariants
  still hold — the consistency checker runs clean.

  Watch still shows 0 on this campaign, and I'd rather flag that than distort
  the data further. The arithmetic doesn't allow both: with 3,600 total drops
  across 9 questions, funding a >20% question and a 10%+ question leaves the
  tail at implausible near-zero rates. I tried it. Healthcare (Q4, 13.8%) and
  Employee (Q4, 15.4%) both sit in Watch — so a campaign switcher on this page
  would exercise all three tiers immediately. Small change if you want it.

  "Completion rate" is cumulative — share of all invited still in the survey
  after that question. Read per-question it would be exactly 100 − dropoutRate
  and carry no new signal. The column header says cumulative beneath it. Say the
  word if you meant the per-question reading.
